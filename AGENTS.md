# Map-building knowledge

For a new region or changes to map geometry, terrain, source data, or rendering, read
[docs/map-building-playbook.md](docs/map-building-playbook.md). It records the failure modes,
reusable fixes, implementation references and validation checklist learned from earlier maps.

When fixing another map defect, record its symptom, root cause, reusable rule, code/test references,
and applicability limits there. Keep city-specific source details in the corresponding region notes.
Do not carry Richmond-specific source services, units or thresholds into a new place without checking them.

See [CLAUDE.md](CLAUDE.md) for project conventions and commands, and
[docs/map-styles.md](docs/map-styles.md) for the rendering-style registry/template.
